서버에 필요한 것은 Node 20 이상과 git 둘이다. 빌드는 없다 — npm ci 를 인터넷이 되는 머신에서 한 번 돌리고, 나온 디렉터리를 통째로 옮겨 node server/main.mjs 로 띄운다. npm · 컴파일러 · 네이티브 모듈 · DB 는 서버에 없어도 된다. git 만은 예외다 — 문서 저장소가 git 저장소라 git 이 없으면 기동 자체가 안 된다. 이 문서는 그 순서 — 설치할 것, 준비, 배치, 계정, 설정, 기동, 확인, 운영 — 를 한 장에 모은다.

01

한눈에

실행 단위는 레포 디렉터리 하나다. 의존성은 fastify 하나(딸린 패키지 41개, 약 14MB)뿐이고 네이티브 모듈이 없어 node_modules 를 그대로 옮기면 어느 리눅스에서든 돈다. 데이터는 서버가 AKG_HOME 아래에 git 저장소로 만든다.

준비 머신 · Node + 인터넷 → npm ci · npm test → akg.tar.gz (코드 + node_modules) → 서버 · Node 20+ · git → users.json (0600) → node server/main.mjs → BE · AKG_URL 로 읽는다 브라우저 · 대시보드 저작자 · akg push

서버로 들어오는 길은 셋 — BE 는 읽기만, 사람은 대시보드에서 읽고 고치고, 저작자는 CLI 로 md 를 올린다. 전부 같은 HTTP 포트 하나다

기동에 필요한 것은 셋이고, 없으면 서버가 뜨지 않는다(설계 §11 S1 — fail-closed).

것어디서 오나없으면
git 바이너리서버 OS 패키지git init: spawnSync git ENOENT 로 즉시 종료
users.json§05 의 CLI 가 만든다users.json 없이는 기동하지 않습니다(S1) 로 즉시 종료
깨끗한 store서버가 첫 기동에 만든다더티 트리 · index.lock 이 있으면 기동 거부(S9)
02

서버에 설치할 것

필수는 Node 와 git 둘이다. 나머지는 확인용이라 없어도 서버는 뜬다.

것필수왜
Node 20 이상필수package.json 의 engines 가 >=20. fastify 5 가 그 아래에서 안 돈다. 실측은 v24. 배포판 패키지든 tarball 을 풀어 둔 것이든 node 실행 파일 하나면 된다.
git필수문서 저장소(AKG_HOME/store)가 git 저장소다. 서버가 git init · add · commit · log · show 를 자식 프로세스로 부른다. 커밋 author 가 곧 감사 기록이라 대체 수단이 없다. 계정 설정(user.name)은 서버가 store 안에 직접 넣으니 전역 설정은 필요 없다.
curl권장/health 와 문서 목록을 쳐 보는 데 쓴다(§08).
npm불필요서버에서 설치할 것이 없다. node_modules 는 준비 머신에서 만들어 같이 옮긴다(§03). Node 를 tarball 로 풀었다면 npm 도 따라오지만 안 써도 된다.
컴파일러 · python · make불필요네이티브 모듈이 0개다. 빌드 단계가 없다.
DB · 브라우저불필요저장은 파일 + git 이고, 대시보드는 정적 파일 셋(public/)을 서버가 직접 낸다. 번들러도 없다.
리버스 프록시외부 노출 시서버는 기본 127.0.0.1 에만 묶인다. 다른 박스에서 붙게 하려면 같은 호스트의 nginx 같은 프록시가 HTTPS 를 받고 넘긴다(§09).

설치 확인은 두 줄이다. 첫 줄의 주 버전이 20 이상이어야 한다.

node -v      # v20.x 이상 · 실측 v24.12.0
git --version
03

준비 — 인터넷 되는 곳에서

npm ci 는 레지스트리에서 패키지를 받는다. 그래서 개발 PC 나 CI 처럼 밖이 열린 머신에서 한 번 돌리고, 코드와 node_modules 를 한 아카이브로 묶는다. 서버의 Node 주 버전과 같은 Node 로 돌리면 가장 안전하지만, 네이티브 모듈이 없어 버전이 달라도 문제가 되지 않는다.

  1. 받기배포할 커밋을 체크아웃한다. git log -1 의 해시를 적어 둔다 — 서버에는 .git 을 안 가져가므로 어느 판인지는 이 메모가 유일한 기록이다.
  2. 의존성npm ci — package-lock.json 그대로 설치한다. devDependencies 가 없어 --omit=dev 는 의미가 없다.
  3. 테스트npm test — node --test 로 전체 스위트(218). 서버 · CLI · 렌더까지 실제 소켓으로 도는 테스트라 이게 통과하면 그 Node 로 서버가 뜬다는 뜻이다.
  4. 묶기필요한 디렉터리만 tar 로 묶는다. test/ · docs/ · examples/ 는 서버에 없어도 되지만 크기가 작아 통째로 묶어도 무방하다. .git 과 .akg-data 는 뺀다.
git clone <repo> akg && cd akg
git checkout <배포 커밋>
npm ci
npm test                                   # ✔ 218 · ✖ 0
tar czf ../akg.tar.gz \
  --exclude=.git --exclude=.akg-data \
  bin server src schemas public node_modules package.json package-lock.json examples
ls -la ../akg.tar.gz                       # 수 MB

서버에 필요한 디렉터리는 다섯이다 — server/(HTTP 서버) · src/(스키마 검증 · 렌더 · 클라이언트) · schemas/(문서 타입별 JSON Schema, 서버가 기동 때 읽는다) · public/(대시보드) · bin/(CLI). examples/ 는 §08 의 스모크에 쓸 예시 스킬 md 가 들어 있어 같이 가져가면 편하다.

04

서버 배치

코드와 데이터를 다른 디렉터리에 둔다. 코드는 판을 올릴 때 통째로 바꾸고, 데이터는 그대로 남아야 해서다. 기본값 AKG_HOME=./.akg-data 는 현재 디렉터리 기준이라 코드 안에 데이터가 생긴다 — 항상 절대 경로로 잡는다.

/opt/akg/
├── app/                        # §03 아카이브를 푼 것 — 판 교체 때 통째로 바뀐다
│   ├── server/main.mjs         #   진입점
│   ├── server/cli/akg-user.mjs #   계정 CLI(§05)
│   ├── bin/akg.mjs             #   저작자 CLI(push · sync)
│   ├── public/  schemas/  src/
│   └── node_modules/
├── data/                       # AKG_HOME — 백업 단위 · 판 교체와 무관
│   ├── users.json              #   계정 · 토큰 해시 — 0600, git 밖(§05)
│   └── store/                  #   문서 저장소 — 서버가 첫 기동에 git init 한다
│       ├── domain-skill/<id>.json
│       └── rendered/domain-skill/<id>/SKILL.md
└── akg.env                     # §06 — 토큰은 안 들어가지만 600 으로
sudo useradd -r -m -d /opt/akg -s /sbin/nologin akg
sudo mkdir -p /opt/akg/app /opt/akg/data
sudo tar xzf akg.tar.gz -C /opt/akg/app
sudo chown -R akg:akg /opt/akg

전용 계정으로 돌린다. users.json 은 소유자만 읽을 수 있어야 서버가 뜨고(S1), store 의 커밋도 그 계정이 남긴다. 판을 올릴 때는 app/ 만 새 아카이브로 갈고 재기동한다 — data/ 는 손대지 않는다.

05

계정과 토큰

인증 상태는 users.json 파일 하나다. 서버 API 로는 못 만들고 CLI 가 파일을 직접 쓴다. 사용자 0명이면 서버가 안 뜬다 — 첫 기동 전에 최소 한 명은 만든다.

CLI 는 AKG_HOME 을 보지 않는다. AKG_USERS_PATH 만 보고, 기본은 현재 디렉터리의 ./.akg-data/users.json 이다. 디렉터리는 만들어 주지 않으니 data/ 가 먼저 있어야 한다.

cd /opt/akg/app
export AKG_USERS_PATH=/opt/akg/data/users.json
sudo -u akg -E node server/cli/akg-user.mjs add editor1 editor
# 발급됨 — id=editor1 role=editor expiresAt=2026-12-22T01:28:20.620Z
# 토큰(다시 표시되지 않습니다): 114499e8c7baa21270abece1edb960bbe8cdbd41d6ccbfbc
sudo -u akg -E node server/cli/akg-user.mjs list
# editor1	editor	expiresAt=2026-12-22T01:28:20.620Z
sudo -u akg -E node server/cli/akg-user.mjs revoke editor1

토큰은 그 자리에서 한 번만 보인다. 파일에는 sha256 해시만 남아 잃어버리면 add 로 다시 발급한다(같은 id 로 add 하면 덮어쓴다). 만료는 발급일 + 90일이고 CLI 옵션이 없다 — 연장은 재발급이다. 서버는 요청마다 파일을 다시 읽으므로 add · revoke 는 재기동 없이 바로 먹는다.

역할

역할할 수 있는 것누구에게
viewer읽기 — 문서 목록 · 문서 · 색인 · 번들. akg sync 가 이걸로 돈다.익명 읽기(§06 AKG_ANON_READ)가 켜져 있으면 토큰 없이도 같은 권한이라 따로 만들 일이 드물다. BE 도 토큰 없이 읽는다.
editor문서 만들기 · 고치기 — akg push, 대시보드의 저장.스킬 저작자. 대시보드에서 편집하려면 이 토큰으로 로그인한다.
approvereditor + 승격 · 삭제.리뷰어 · 운영자.
agent제안(proposal) · 배치 · 카탈로그 갱신. 사람 사다리 밖의 별도 역할.자동화(에이전트 스킬). 문서를 직접 고치지 못하고 제안 큐로 보낸다.

인증 실패는 IP 당 5분에 20회를 넘기면 잠시 거절된다(S14). 토큰이 만료 · 회수됐는데 계속 부르는 클라이언트가 있으면 그 IP 의 정상 요청도 같이 막히니, 401 이 보이면 먼저 토큰부터 갈아 끼운다.

06

설정 — 환경 변수

설정은 여섯 개 환경 변수가 전부고, 파일은 없다. 서버는 .env 를 읽지 않는다 — 셸에서 export 하거나 systemd 의 EnvironmentFile 로 넣는다.

변수기본뜻
AKG_HOME./.akg-data데이터 루트. 아래 둘의 기본 경로가 여기서 나온다. 절대 경로로 — 상대 경로면 작업 디렉터리에 따라 다른 store 를 본다.
AKG_STORE_DIRAKG_HOME/store문서 저장소(git). 없으면 서버가 git init 하고 init store 커밋 하나로 시작한다. 있으면 깨끗한지 검사하고 더티면 기동 거부.
AKG_USERS_PATHAKG_HOME/users.json계정 파일. 서버와 CLI 가 같은 파일을 봐야 한다 — CLI 는 이 변수만 읽으니 둘 다 명시하는 편이 안전하다.
AKG_HOST127.0.0.1바인드 주소. 기본은 루프백 — 같은 박스의 프록시만 닿는다(S2). 프록시 없이 사내망에 바로 열려면 0.0.0.0. 그때는 방화벽으로 범위를 좁힌다.
AKG_PORT8787수신 포트.
AKG_ANON_READ1토큰 없는 읽기 허용. 기본 켜짐이라 BE 와 브라우저가 토큰 없이 읽는다. 0 이면 읽기에도 viewer 이상 토큰이 필요하고, BE 에는 AKG_TOKEN 을 넣어야 한다. 쓰기는 값과 무관하게 항상 토큰이다.

운영 예시 — 환경 파일

# /opt/akg/akg.env — KEY=value 한 줄씩, export 없이
AKG_HOME=/opt/akg/data
AKG_STORE_DIR=/opt/akg/data/store
AKG_USERS_PATH=/opt/akg/data/users.json
AKG_HOST=127.0.0.1
AKG_PORT=8787
AKG_ANON_READ=1

클라이언트 쪽 변수

서버가 아니라 bin/akg.mjs(저작자 PC)와 BE 가 읽는 것들이다. 서버 환경 파일에는 안 들어간다.

변수누가뜻
AKG_SERVERakg CLI허브 주소. 없으면 --server, 그것도 없으면 미러의 meta.json 에 적힌 지난번 주소.
AKG_TOKENakg CLI · BECLI 는 이 변수 또는 ~/.claude/akg/token(0600). push 는 토큰 없으면 no token 으로 exit 1. BE 는 있으면 Authorization: Bearer 로 보낸다.
AKG_MIRROR · AKG_SKILLS_DIRakg CLIsync 가 쓰는 곳. 기본 ~/.claude/akg · ~/.claude/skills.
AKG_URL · AKG_REFRESH_SECONDSBEBE 가 스킬을 읽어 오는 허브 주소와 재확인 주기(기본 300초). BE 배포 가이드 §05.
07

띄우기 · 내리기

세 가지 길이 있다. 처음은 포그라운드, 리허설은 nohup, 상시 운영은 systemd. 어느 길이든 명령은 node server/main.mjs 하나다.

포그라운드 — 처음 한 번은 이렇게

기동 실패는 한 줄로 나오고 exit 1 이다(akg server 기동 실패: <이유>). 성공하면 listening 한 줄이 뜨고 그 뒤로는 요청 로그를 찍지 않는다. Ctrl-C 로 내린다.

cd /opt/akg/app
set -a; . /opt/akg/akg.env; set +a
sudo -u akg -E node server/main.mjs
# akg server listening on http://127.0.0.1:8787 (store=/opt/akg/data/store)
# 다른 셸에서
curl -s localhost:8787/health
# {"version":"0.1.0","storeRev":"b7a9da14…"}

nohup — 백그라운드 + PID 파일

cd /opt/akg/app
set -a; . /opt/akg/akg.env; set +a
nohup node server/main.mjs > /opt/akg/akg.log 2>&1 &
echo $! > /opt/akg/akg.pid
# 내리기 — SIGTERM 이면 바로 끝난다. 진행 중인 커밋은 큐가 직렬이라 끊기지 않는다
kill "$(cat /opt/akg/akg.pid)"

systemd — 상시 운영

node 는 절대 경로로 적는다. nvm · asdf 로 깐 Node 는 /usr/bin/node 에 없고 서비스 계정의 셸 초기화도 안 타므로 which node 결과를 그대로 넣는다.

# /etc/systemd/system/akg.service
[Unit]
Description=akg knowledge hub
After=network-online.target
Wants=network-online.target

[Service]
User=akg
WorkingDirectory=/opt/akg/app
EnvironmentFile=/opt/akg/akg.env
ExecStart=/usr/bin/node /opt/akg/app/server/main.mjs
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now akg
systemctl status akg
journalctl -u akg -f                      # 기동 줄과 기동 실패 사유만 나온다
08

확인

떴다는 것과 문서가 오간다는 것은 다르다. 헬스 다음에 들어오는 길 셋 — 대시보드 · CLI · BE — 을 각각 본다.

  1. 살아 있나curl -s localhost:8787/health → {"version":…,"storeRev":…}. storeRev 는 store 의 HEAD 커밋이다 — 문서를 올릴 때마다 바뀐다.
  2. 대시보드브라우저로 http://<host>:8787/. 읽기는 로그인 없이 되고(익명 읽기 기본), 오른쪽 위 로그인 에 §05 의 토큰을 붙여 넣으면 편집이 열린다. 프록시 뒤라면 프록시 주소로.
  3. CLI 로 스킬 하나저작자 PC 든 서버든 bin/akg.mjs 가 있는 곳에서 예시 md 를 올린다. 같은 파일을 두 번 올리면 두 번째는 updated 로 나온다 — 멱등이다.
  4. BE 가 읽나BE 의 AKG_URL 을 이 주소로 두고 POST /admin/reload → outcome 이 fetched, GET /api/fdc/v1/skills 에 이름이 보이면 끝까지 붙은 것이다.
cd /opt/akg/app
AKG_TOKEN=<editor 토큰> AKG_SERVER=http://127.0.0.1:8787 \
  node bin/akg.mjs push domain-skill examples/domain-skill/fdc-explain-sensor-origin.md

운영

로그와 감사

서버는 요청 로그를 남기지 않는다(fastify logger 꺼짐). 누가 무엇을 바꿨는지는 store 의 git 이력이 답이다 — 커밋 author 가 토큰의 사용자 id 고, 대시보드의 감사 화면과 GET /api/audit 이 같은 이력을 보여 준다. git -C /opt/akg/data/store log 로 직접 봐도 된다. 읽기만 한다 — 쓰면 S9 에 걸려 다음 기동이 거부된다.

백업 · 복구

백업 단위는 AKG_HOME 디렉터리 하나다. store 는 git 저장소라 git clone 이나 git bundle 로도 되고, users.json 은 git 밖이라 파일째 같이 챙긴다. 복구는 서버를 내리고 디렉터리를 되돌린 뒤 git status 가 깨끗한지 보고 다시 띄운다.

판 올리기 · 되돌리기

app/ 을 새 아카이브로 갈고 재기동한다. data/ 는 그대로다. 이전 아카이브를 옆에 두면 되돌리기도 디렉터리 하나 바꾸고 재기동이다. 문서 스키마가 바뀌는 판(예: domain-skill 의 md 전환)은 옛 문서가 새 서버에서 거절될 수 있다 — 그 판의 changelog(json-spec.md 첫머리)를 먼저 본다.

설정 변경

환경 변수는 기동 때 한 번 읽는다 — 바꾸면 재기동이다. 예외는 계정 — users.json 은 요청마다 읽어 add · revoke 가 바로 먹는다. 문서는 API 로만 바뀌고 재기동과 무관하다.

보안 — 있는 것과 없는 것

  • 쓰기는 전부 토큰(S1). 토큰은 해시로만 저장, 90일 만료, IP 당 실패 20회/5분 제한(S14).
  • 읽기는 기본 익명 허용. 문서가 프롬프트 주입 통로가 되는 위협(S3)은 쓰기 쪽 방어라 읽기 개방과 무관하지만, 사내망 밖에 열지는 않는다.
  • 바인딩은 루프백(S2). 외부 노출은 같은 호스트의 HTTPS 리버스 프록시가 맡고, 앱 포트 직접 접속은 방화벽으로 막는다. 프록시가 넘기는 X-Forwarded-* 를 서버가 믿지는 않는다 — 요청 IP 는 소켓 기준이라 프록시 뒤에서는 실패 제한이 프록시 IP 하나로 묶인다.
  • 모든 응답에 strict CSP(default-src 'self')와 nosniff. 대시보드는 인라인 스크립트가 없다.
  • 요청 본문 512KB 상한(S13). id 는 파일명이 되므로 소문자 · 숫자 · _ . - 만(S11).
  • HTTPS · SSO · 다중 인스턴스는 서버 안에 없다. 인스턴스는 하나만 — 실패 카운터와 쓰기 큐가 프로세스 안에 있다.
